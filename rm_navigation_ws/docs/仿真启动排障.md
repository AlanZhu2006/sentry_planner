# 仿真启动排障指南

## 问题 1：pointcloud_to_laserscan_sim 脚本找不到

**现象**：`can't open file '.../pointcloud_to_laserscan_sim.py': No such file or directory`

**原因**：脚本安装到 `lib/`，source nav_ws 再 source rm_navigation_ws 时路径解析可能异常。

**修复**：脚本改为安装到 `share/rm_nav_bringup/scripts/`，launch 使用该路径。

---

## 问题 2：spawn_entity 超时 / 机器人未生成

**现象**：`Entity pushed to spawn queue, but spawn service timed out waiting for entity to appear`

**原因**：spawn_entity 与 gzserver 启动顺序不当，或 Gazebo 加载世界较慢。

**修复**（已应用）：`pb_rm_simulation/launch/rm_simulation.launch.py`
- 先启动 gzserver，再延迟 10 秒启动 spawn_entity
- spawn_entity 增加 `-timeout 60` 参数

---

## 问题 3：map 坐标系不存在 / Invalid frame ID "map"

**现象**：
- RViz 报错：`Invalid frame id: map passed to argument frame does not exist`
- `local_costmap: Timed out waiting for transform... frame does not exist`

**原因**：
1. 未使用 `mode:=nav` 或未指定 `localization`，导致 map_server/AMCL 未启动
2. `localization:=slam_toolbox` 需要 **pose-graph 格式**（`.posegraph`），而 `map/RMUL` 仅有 occupancy grid（`.yaml` + `.pgm`），slam_toolbox 无法加载
3. AMCL 需在 RViz 中设置 **2D Pose Estimate** 后才会发布 `map->odom`，在此之前 `map` 不存在

**解决**：
1. 使用正确启动参数（必须包含 `mode:=nav` 和 `localization:=amcl`）：

```bash
ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL mode:=nav localization:=amcl lio:=fastlio nav_rviz:=True
```

2. RViz 默认 Fixed Frame 已改为 `odom`，启动时不再报错；待 AMCL 就绪后可在 RViz 中手动改回 `map`
3. 在 RViz 中点击 **2D Pose Estimate**，在地图上拖出机器人初始位姿，AMCL 才会发布 `map` 坐标系
4. 若需使用 slam_toolbox 定位，需事先在 mapping 模式下建图并序列化保存为 pose-graph，再在 localization 模式下加载

---

## 问题 4：fastlio / ground_segmentation 崩溃（libusb_set_option）

**现象**：`symbol lookup error: libusb_set_option`

**原因**：PCL 与系统 libusb 版本不兼容。

**临时解决**：仿真模式下可不依赖 LIO，使用 slam_toolbox 或 AMCL。若必须用 fastlio，可尝试：
```bash
export LD_PRELOAD=/lib/x86_64-linux-gnu/libusb-1.0.so.0
```

## 推荐启动命令（RMUL 仿真 + 导航）

**使用 Gazebo 里程计（推荐，定位更稳，减少乱飞）：**
```bash
ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL mode:=nav localization:=amcl use_gazebo_odom:=true nav_rviz:=True
```
- `use_gazebo_odom:=true` 时自动不启动 Fast-LIO，由 Gazebo 发布 odom->base_link
- 仿真里程计无漂移、无跳变，AMCL 定位更稳定

**使用 Fast-LIO 里程计（原方式）：**
```bash
ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL mode:=nav localization:=amcl lio:=fastlio nav_rviz:=True
```

说明：
- `localization:=amcl`：使用 RMUL.yaml/pgm  occupancy grid 地图
- 需在 RViz 中设置初始位姿（2D Pose Estimate）后再发送导航目标

## 卡顿时可用的轻量化选项

若仿真仍然卡顿，可尝试：

1. **headless 模式**（无 Gazebo GUI，GPU 负载大幅降低）：
```bash
ros2 launch rm_nav_bringup bringup_sim.launch.py \
  world:=RMUL mode:=nav localization:=amcl lio:=fastlio headless:=True nav_rviz:=True
```

2. **关闭 Nav RViz**（仅保留 LIO 或无需可视化时）：
```bash
nav_rviz:=False
```

3. 当前配置已做多项降负优化：Gazebo 物理 100Hz、Livox 点云约 1/4 密度、Fast-LIO/AMCL/Nav2 参数均已调低。
