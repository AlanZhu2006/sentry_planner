NYUSH sentry communication commands
最后更新：2026-03-19

当前这一次 bridge 输出
-----------------------
MCU serial : /dev/ttyACM0
Vision PTY : /dev/pts/2
Radar PTY  : /dev/pts/3

注意
----
1. 真实口 /dev/ttyACM0 只能给 sentry_bridge.py 占用。
2. 视觉程序连 Vision PTY；雷达/导航程序连 Radar PTY。
3. bridge 每次重启，/dev/pts/N 都可能变化；每次都以 bridge 当次打印结果为准。
4. 建议先把车架空，再做 one-shot / keyboard 测试。
5. 当前默认已进入“只用 vx vy”调试模式：Nav2 自带 `wz` 默认会被忽略。

2. Radar PTY 常用测试
=====================

当前这次启动请使用：
Radar PTY = /dev/pts/3

2.1 官方雷达 mock 工具

2.3 serial_sender 单次发速度
----------------------------

----------------------------

键位：

A/D 左右
Q/E 旋转
SPACE 急停
ESC 退出

2.5 启动行为树通讯适配层

python3 /home/nyu/Codespace/nyush-rm-vision/serial_sender.py --port /dev/pts/3 --ros2 --topic /cmd_vel_chassis_bt

------------------------------

6. 快速排障
===========

6.1 bridge 起不来
-----------------
lsof /dev/ttyACM0

6.2 serial_sender 没反应
------------------------
确认它连的是 /dev/pts/3，不是 /dev/ttyACM0；并确认它监听的是 /cmd_vel_chassis_bt

6.3 视觉没反应
--------------
确认 sentry.yaml 里的 com_port 是 /dev/pts/2

6.4 行为树没动
--------------
确认 bt_comm_adapter.py 正在运行，并检查 /game_status /robot_status /all_robot_hp /detector/armors /cmd_vel_chassis_bt

6.5 bridge 重启后 PTY 变了
--------------------------
把所有 /dev/pts/2 和 /dev/pts/3 都替换成新打印出来的 PTY

6.6 旧文档里还写 /dev/ttyACM0
------------------------------
在当前桥接架构下，serial_sender 和视觉程序都不应该再直连 /dev/ttyACM0
